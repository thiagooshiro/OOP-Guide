O que é POO

Orientação a Objetos é uma forma de organizar código em torno de entidades — objetos que agrupam dados e comportamento num lugar só.

Em vez de espalhar funções e variáveis pelo código, você cria classes que descrevem o que um componente é e o que ele sabe fazer.

Um ProductCard sabe criar seu próprio elemento, preencher seus dados e reagir a cliques — tudo encapsulado numa classe.

Mesmo componente. Duas abordagens.

Functional

Componente funcional

"Alguém lá fora decide o que acontece comigo." 
function createWarningCard(message) {
  const card = document.createElement('div');
  card.innerHTML = `
    <strong>Aviso</strong>
    <p>${message}</p>
  `;
  return card;
}

// comportamento definido fora:
btn.addEventListener('click', () => {
  card.style.display = 'none';
});
Class Based

Componente com classe

"Eu sei o que fazer quando me clicam." 
class WarningCard {
  constructor(message) {
    this.message = message;
  }

  close() {
    this.element.remove();
  }
}

Encapsulamento

Encapsulamento é o nome técnico pra uma ideia simples: cada coisa cuida de si mesma.

Uma classe bem encapsulada cria sua própria estrutura, controla seus eventos e atualiza sua própria UI. Quem usa a classe não precisa saber como ela funciona por dentro — só precisa saber o que ela oferece.

modal.open(product) — não importa como o modal foi construído. Você chama, ele abre.

Herança

Herança permite que uma classe reuse tudo que outra já tem — e só mude o que precisa ser diferente. Nos exemplos abaixo, a classe filha herda estrutura e comportamento da classe base, sobrescrevendo apenas o visual.

Card vs HighlightedCard

ModalBase → ProductModal

Composição

Composição é quando uma classe usa outras classes como peças. Em vez de fazer tudo sozinha, ela delega — cada componente cuida do que é seu, e uma classe orquestradora conecta tudo.
